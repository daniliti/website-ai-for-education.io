# «ИИ для образования» — онлайн-курс для GitHub Pages

Практический курс для преподавателей колледжа: 16 академических часов, 8 модулей, вход по логину и паролю без регистрации.

## Что внутри

- `index.html` — весь онлайн-курс: модули, практики, самопроверка, библиотека запросов, итоговый проект.
- `auth.js`, `auth-data.js` — проверка входа; открытых паролей в репозитории нет.
- `files/` — методические рекомендации, рабочая тетрадь и SCORM-пакет.
- `.nojekyll` — отключает обработку Jekyll, чтобы GitHub Pages отдавал файлы как есть.
- `robots.txt` — закрывает индексацию поисковиками; курс открывается по прямой ссылке.
- `404.html` — возвращает на главную страницу курса.

## Как опубликовать

### Вариант 1. Через сайт GitHub

1. Создайте новый **публичный** репозиторий, например `ai-for-education`.
2. Распакуйте этот архив и загрузите **содержимое папки** `github-pages` в корень репозитория.
   Важно: `index.html` должен лежать в корне, а не внутри вложенной папки.
3. Откройте **Settings → Pages**.
4. В разделе **Build and deployment** выберите:
   - **Source:** Deploy from a branch;
   - **Branch:** `main`;
   - **Folder:** `/ (root)`.
5. Нажмите **Save** и подождите 1–2 минуты.
6. Адрес курса будет выглядеть так:
   `https://USERNAME.github.io/ai-for-education/`

### Вариант 2. Через git

```bash
cd github-pages
git init -b main
git add .
git commit -m "Add AI for Education online course"
git remote add origin https://github.com/USERNAME/ai-for-education.git
git push -u origin main
```

Затем включите GitHub Pages: **Settings → Pages → Deploy from a branch → main → / (root)**.

## Как выдать доступы

- Логины: `ped01`–`ped60`.
- Пароли выдаёт преподаватель. В этом репозитории их нет — только хеши.
- Не загружайте в GitHub административный файл с открытыми паролями.
- Участник открывает ссылку с любого устройства и входит со своей парой логин/пароль.

## Важно

- Это клиентская проверка доступа для учебной группы. Она защищает от случайного входа, но не является полноценной системой безопасности: код страницы можно исследовать, а проверку — обойти. Для строгой авторизации нужен сервер или LMS.
- Прогресс сохраняется в `localStorage` браузера **на конкретном устройстве**. Войти можно с любого устройства, но прогресс между устройствами не синхронизируется. Для синхронизации нужен backend или LMS.
- GitHub Pages для бесплатного аккаунта обычно требует **публичный** репозиторий. Приватный репозиторий может потребовать платный план.
- Не добавляйте в публичный репозиторий папку `admin/` с открытыми паролями.

## Обновление курса

Замените файлы в репозитории и сделайте commit. GitHub Pages обновится автоматически после публикации.

## Проверка после публикации

1. Откройте `https://USERNAME.github.io/REPO/`.
2. Убедитесь, что появился экран входа.
3. Войдите тестовым логином.
4. Проверьте ссылки на PDF в разделе «Методисту» и «Материалы».
5. Выйдите и войдите другим логином — прогресс должен быть отдельным.
